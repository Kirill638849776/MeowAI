# Contributing / Правила участия

Спасибо за интерес к проекту.  
Отправляя pull request (PR), вы автоматически соглашаетесь соблюдать эти правила.

## 1. Общие принципы

- Уважайте других участников.
- Один PR — одна задача.
- Перед крупными изменениями сначала создайте issue и дождитесь ответа мейнтейнеров.
- Описывайте изменения понятно: что сделано, зачем и как это проверить.
- Не меняйте файлы, которые не относятся к вашей задаче.
- Будьте готовы внести правки по замечаниям ревьюеров.

## 2. Что приветствуется

- Исправление багов.
- Улучшение документации.
- Добавление тестов.
- Улучшение читаемости и безопасности кода.
- Полезные оптимизации без скрытых побочных эффектов.

## 3. Правила для Pull Request

1. PR должен иметь понятное название и описание.
2. В PR не должно быть лишних, случайных или несвязанных изменений.
3. Если добавлен новый код, по возможности добавьте тесты.
4. Все автоматические проверки должны проходить.
5. PR может быть отклонён или закрыт без подробного объяснения, если нарушает правила проекта.
6. Все PR проходят автоматическую и ручную модерацию на вредоносный код.

## 4. Строго запрещается

### 4.1. Вредоносный код

Запрещается вносить, скрывать или пытаться протащить в проект:

- malware, вирусы, червей, трояны, шифровальщики;
- backdoor, скрытые учётные записи, удалённое управление без согласия;
- код для кражи данных, паролей, токенов, cookie или ключей;
- эксплойты, обходы авторизации, обходы безопасности;
- скрытые команды, подозрительные бинарники;
- код, который причиняет вред пользователям, серверам или инфраструктуре;
- код, который нарушает приватность или собирает данные без явного согласия.

### 4.2. Делать ИИ злым

Запрещается добавлять код, промпты, модели, настройки или поведение, целью которых является сделать ИИ:

- злым, враждебным или агрессивным;
- манипулятивным или обманчивым;
- вредоносным по отношению к пользователям;
- нарушающим приватность;
- обходящим ограничения безопасности;

ИИ в проекте должен оставаться безопасным, полезным и подконтрольным.

### 4.3. Спам PR

Запрещается:

- отправлять бессмысленные PR;
- дублировать уже существующие PR;
- массово создавать однотипные PR;
- использовать PR для рекламы;
- отправлять автоматически сгенерированный мусор без реальной ценности;
- флудить комментариями и упоминаниями.

Спам PR может привести к блокировке без предупреждения.

### 4.4. Редактирование CI

Запрещается редактировать `ci.yml`  
(включая `.github/workflows/ci.yml` и другие CI-конфиги) в рамках обычных PR.

Если изменение CI действительно необходимо:

1. Сначала создайте issue.
2. Получите явное одобрение мейнтейнеров.
3. Только после этого отправьте отдельный PR с описанием причины изменения.

### 4.5. Обфускация исходного кода

Запрещается обфусцировать исходный код:

- использовать намеренно запутанный, нечитаемый или скрытый код;
- прятать логику с помощью шифрования, кодирования, динамической генерации без прозрачной причины;
- заменять нормальный исходный код минифицированными или сгенерированными файлами без явного согласования.

Весь код должен быть читаемым и проверяемым.  
Если обфускация действительно нужна для legitimate-задачи, сначала создайте issue и получите явное одобрение мейнтейнеров.  
PR с обфусцированным кодом может быть отклонён или закрыт без предупреждения.

## 5. Модерация

Все PR проходят:

- автоматическую проверку: линтеры, тесты, сканеры секретов, поиск подозрительных паттернов, проверка на вредоносный код;
- ручную проверку: мейнтейнеры изучают код, намерения и возможные риски.

Мейнтейнеры могут:

- запросить изменения;
- отклонить PR;
- закрыть PR;
- удалить комментарии;
- заблокировать пользователя;
- сообщить о вредоносной активности администрации платформы.

Решение мейнтейнеров является окончательным.

## 6. Безопасность

Если вы нашли уязвимость, не публикуйте её в PR и issue.  
Сначала свяжитесь с мейнтейнерами приватно.

## 7. Лицензия и авторство

Отправляя PR, вы подтверждаете, что:

- имеете право внести эти изменения;
- не нарушаете чужие авторские права;
- согласны на распространение вашего вклада на условиях лицензии проекта.

## 8. Заключение

Главное правило: не вредить проекту, пользователям и сообществу.  
Если сомневаетесь — сначала создайте issue и спросите.
